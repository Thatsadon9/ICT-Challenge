# หลักสูตรจากพื้นฐานสู่การฝึกแข่งขัน ICT Challenge 2026

## 1. หลักฐานและผลต่อการเตรียมตัว

ตรวจข้อมูลวันที่ 25 ตุลาคม 2569 โดยให้กติกา 2026 เป็นหลัก ไม่ยกกติกาเก่ามาใช้แทน

| ปี / หลักฐาน | ข้อค้นพบ | ผลต่อแผน |
|---|---|---|
| 2023: ข่าวสรุปของ SIT [R4] | มีคัดเลือกและรอบชิงแบบเลือกหมวด/ระดับคำถาม | ฝึกตอบความรู้หลายด้านภายใต้แรงกดดัน ไม่สรุปว่าข้อใดออกซ้ำ |
| 2024: ข่าวสรุปของ SIT [R3] | คัดจากผู้แข่งขันรายบุคคลไปสู่ 10 ทีมรอบชิง และมีการเลือกคำถาม | ทุกคนต้องมีพื้นฐานกว้างก่อนแบ่งคนเชี่ยวชาญ |
| 2025: กติกาต้นฉบับ [R2] | หมวด Network/OS, Programming, Hardware/Cloud, Smart System/AI; รอบก่อนชิงเน้น C, Java, Python | เรื่องระบบและการอ่านโค้ดยังมีเหตุผลให้เตรียม แต่ไม่ใช่หลักฐานความถี่ข้อสอบ |
| 2026: หัวข้อและ PDF [R1, R5] | จัด 4 หมวดใหม่ให้ชัดด้าน Cybersecurity, Data/Generative AI และ Productivity; รอบรองมีเขียนโปรแกรม | เพิ่มการฝึกใช้เหตุผลด้านความปลอดภัย ข้อมูล เครื่องมือสำนักงาน และการเขียนโค้ดจริง |

ยังไม่พบคลังข้อสอบเก่าพร้อมเฉลยที่ตรวจสอบที่มาได้จากการค้นชื่อการแข่งขันร่วมกับ “ข้อสอบ”, “ข้อสอบเก่า”, “ตัวอย่างข้อสอบ”, “แนวข้อสอบ”, “เฉลย” และค้นเว็บไซต์ SIT การไม่พบจากการค้นนี้ไม่ได้แปลว่าเอกสารดังกล่าวไม่มีอยู่ที่อื่น

ไฟล์กติกา 2024 ที่ผลค้นหาชี้ไปยัง `sitevent-api.sit.kmutt.ac.th` เปิดไม่สำเร็จ จึงใช้ข่าวจาก SIT แทน และไม่อ้างรายละเอียด PDF นั้นเป็นข้อเท็จจริงที่ตรวจแล้ว

## 2. แยกขอบเขตยืนยันจากหัวข้อที่ออกแบบให้ฝึก

**ยืนยัน** = ผู้จัดระบุหมวดหรือทักษะระดับกว้างใน [R1, R5] ส่วนหัวข้อย่อยและระดับความยากด้านล่างเป็น **การออกแบบการสอน** ไม่ใช่สัดส่วนหรือรายการข้อสอบที่ผู้จัดรับรอง

| หมวดที่ยืนยัน | ฐานที่ต้องคล่อง | ระดับประยุกต์ที่ควรฝึก | เสริมเมื่อฐานผ่าน |
|---|---|---|---|
| Network / Infrastructure / Cloud / Security | อุปกรณ์เครือข่าย IP/DNS/DHCP, CPU/RAM/storage, cloud service models, identity/permission | TCP/UDP, subnet เบื้องต้น, VM/container, backup/availability, phishing, hash/encryption | subnet หลายขั้น, วิเคราะห์เหตุขัดข้องและภัยคุกคามจากหลายเงื่อนไข |
| Programming & Algorithms | ตัวแปร เงื่อนไข ลูป ฟังก์ชัน array/string, pseudocode | อ่านโค้ด C/Java/Python, debugging, search/sort, Big-O, เขียนโปรแกรมจากโจทย์ | prefix sum, two pointers, stack/queue, BFS/DFS ขั้นต้น |
| Data Science & AI | ชนิดข้อมูล สถิติพื้นฐาน กราฟ งาน ML หลัก และ GenAI | cleaning, train/validation/test, overfitting, leakage, confusion matrix, prompt และการตรวจคำตอบ | เลือก metric ตามสถานการณ์, เปรียบเทียบวิธีแก้ bias, embeddings/RAG ระดับแนวคิด |
| Foundational ICT & Productivity | หน่วยข้อมูล hardware/software/OS, ไฟล์และเครื่องมือสำนักงาน | สูตร spreadsheet, relative/absolute references, sort/filter/chart, sharing/version history, automation แบบ trigger/action | SQL แบบ SELECT/WHERE/GROUP BY และ workflow หลายขั้นในฐานะทักษะเสริม |

ไม่เริ่มด้วย dynamic programming ขั้นสูง, balanced trees, training neural network จากศูนย์ หรือเจาะลึก framework เพราะยังไม่มีหลักฐานว่าคุ้มกว่าพื้นฐานในเวลาเตรียมที่เหลือ เรื่อง SQL, BFS/DFS และ RAG เป็นหัวข้อเสริมที่อนุมานเพื่อขยายทักษะ ไม่ใช่หัวข้อย่อยที่ผู้จัดระบุโดยตรง

## 3. โครงสร้างบทเรียน

เวลาแต่ละหน่วยประมาณ 60–90 นาที รวมแบบฝึก หลายหน่วยแบ่งเรียนสองวันได้ โดยย่อการบรรยายตามผลวัดพื้นฐานเพื่อให้เข้ากับปฏิทินจริง

| หน่วย | สิ่งที่จะสอน | งานที่ต้องทำได้ก่อนข้าม |
|---|---|---|
| F1 ระบบคอมพิวเตอร์และข้อมูล | input/process/output/storage, CPU/RAM/SSD, bit/byte, binary, Boolean | แปลงหน่วยพร้อมแสดงวิธีคิด และอธิบาย RAM ต่างจาก storage |
| F2 อ่านโค้ดอย่างเป็นระบบ | trace table, ลำดับคำสั่ง เงื่อนไข ลูป ฟังก์ชัน, scope เบื้องต้น | ไล่ค่าโค้ด 5 ชุดและชี้ off-by-one |
| N1 เส้นทางข้อมูลบนเครือข่าย | switch/router/AP, IP/MAC, DNS/DHCP, TCP/UDP, HTTP/TLS | อธิบายจากพิมพ์ URL ถึงได้รับหน้าเว็บ พร้อมแยกหน้าที่บริการ |
| N2 Addressing และ infrastructure | IPv4/subnet พื้นฐาน, private/public, VM/container, storage/backup | คำนวณ /24 และ /26 แบบ IPv4 ปกติ และวิเคราะห์เครื่องช้าหรือเครือข่ายเสีย |
| N3 Cloud | IaaS/PaaS/SaaS, public/private/hybrid, elasticity, shared responsibility | เลือกบริการให้สถานการณ์ 5 ข้อพร้อมเหตุผล |
| N4 Security | CIA, authn/authz, MFA, least privilege, malware/phishing, encryption/hash | จับคู่ภัยกับมาตรการและบอกความเสี่ยงที่ยังเหลือ |
| P1 ภาษาและชนิดข้อมูล | integer division, precedence, arrays/strings, C/Java/Python | อ่าน snippet ที่ให้ผลต่างกันโดยอธิบายกฎภาษาได้ |
| P2 อัลกอริทึมพื้นฐาน | linear/binary search, sort แนวคิด, Big-O, ขอบเขต input | เลือกวิธีค้นหาให้ข้อมูลและประมาณจำนวนงาน |
| P3 เขียนโจทย์จริง | input/output, counter/accumulator, frequency, min/max, string processing | เขียน 3 โจทย์ ทดสอบค่าขอบ ไม่ hardcode ตัวอย่าง |
| P4 ประยุกต์และแก้บั๊ก | prefix sum/two pointers เมื่อเหมาะ, stack/queue; BFS/DFS เฉพาะมีเวลา | อธิบาย invariant และแก้ข้อผิดพลาดจาก test ที่ล้ม |
| D1 ข้อมูลและสถิติ | numeric/categorical, missing/duplicate/outlier, mean/median, กราฟ | ทำความสะอาดตารางเล็กและเลือกกราฟไม่ชวนเข้าใจผิด |
| D2 ML และการประเมิน | supervised/unsupervised/reinforcement, classification/regression, split, metrics | เลือก task/metric และชี้ leakage จากสถานการณ์ |
| D3 GenAI | generation, prompt/context, hallucination, privacy/bias, verification | เขียน prompt มีเป้าหมาย/เงื่อนไข/รูปแบบผล และตรวจข้ออ้าง |
| T1 Spreadsheet | SUM/AVERAGE/COUNTIF/IF, reference, sort/filter, chart | ลากสูตรที่มี `$` ได้ถูกและไม่ทำตารางข้อมูลสลับแถว |
| T2 Digital productivity | formats, collaboration/permission, version history, sources, automation | ออกแบบขั้นตอนรับข้อมูล→ตรวจ→สรุป และกำหนดสิทธิ์เหมาะสม |
| C1 รอบรายบุคคล | ข้อผสม 4 หมวด การอ่านตัวเลือกและบริหารเวลา | ทำข้อใหม่ 40 ข้อใน 60 นาที แล้วอธิบายจุดผิดได้ |
| C2 รอบทีมและรอบชิง | สื่อสารวิธีคิด review โค้ด เลือกหมวดคำถามและตรวจความมั่นใจ | ซ้อมทีม 60 นาที และตอบสถานการณ์ยาก 3 ข้อต่อหมวด |

จำนวน 40 ข้อและโจทย์ซ้อมต่าง ๆ ในแผนเป็นแบบจำลองของหลักสูตร ผู้จัดยังไม่ได้ยืนยันจำนวนข้อรอบ onsite ในแหล่งที่อ่าน

## 4. วิธีเรียนหนึ่งคาบ

คาบ 90 นาที: ทวนจากความจำ 10 → เรียนแนวคิด 20 → ดูตัวอย่างแล้วทำเอง 20 → โจทย์ใหม่จับเวลา 25 → วิเคราะห์ความผิด 15

ถ้ามี 60 นาที: 5 + 15 + 15 + 15 + 10 นาที ถ้ามี 120 นาที เพิ่มเขียนโปรแกรมหรือสถานการณ์ประยุกต์ 30 นาที ไม่เพิ่มแต่เวลาฟังบรรยาย

ในแต่ละเรื่องจะสอน 3 ชั้น:

1. **รู้และแยกได้**: บอกความหมายพร้อมตัวอย่างและข้อที่ดูคล้ายกัน
2. **ทำได้**: คำนวณ ไล่โค้ด เลือกวิธีแก้สถานการณ์
3. **อธิบายภายใต้เวลาได้**: ทำโจทย์ใหม่ บอกเหตุผล และปฏิเสธตัวลวง

แต่ละคาบมี retrieval quiz 3 ข้อและทวนเรื่องที่เคยผิดหลัง 1, 3 และ 7 วัน เกณฑ์ซ้อมคือ ≥80% ในโจทย์ใหม่สองชุด และไม่มีแนวคิดเดิมผิดซ้ำโดยไม่รู้สาเหตุ ตัวเลขนี้เป็นเกณฑ์เรียน ไม่ใช่คะแนนรับประกันเข้ารอบ

บันทึกข้อผิดเป็นตาราง:

| วัน / ข้อ | เรื่อง | สาเหตุ | กฎที่แก้ความเข้าใจ | วันทวน | ผลโจทย์ใหม่ |
|---|---|---|---|---|---|
| ตัวอย่าง D8 | Loop | อ่านปลาย range รวมเข้าไป | ปลาย range ไม่รวม | +1,+3,+7 วัน | รอทำ |

แยกสาเหตุเป็น ไม่รู้แนวคิด / คำนวณผิด / อ่านเงื่อนไขพลาด / syntax ต่างภาษา / รีบเกินไป เพื่อให้การแก้ตรงจุด

## 6. การฝึกทีมสามคน

รอบรายบุคคล: ทุกคนต้องครอบคลุมทั้งสี่หมวด การฝากความรู้ทั้งหมดไว้กับคนเดียวทำให้เสียคะแนนรวมได้

ช่วงเรียนร่วมกันให้มีผู้รับผิดชอบนำทวน: A ดู Network/Security, B ดู Programming, C ดู Data/Productivity แล้วผลัดกันอธิบายให้เพื่อนทำโจทย์ใหม่ได้ บทบาทนี้เปลี่ยนตามจุดแข็งจริง

ช่วงฝึกเขียนโปรแกรมร่วมกัน: หนึ่งคนอ่านโจทย์และสรุป input/output, หนึ่งคนเขียน, อีกคนสร้าง test และตรวจขอบเขต สลับบทบาททุกโจทย์ ทุกคนต้องตรวจ output โดยไม่ยึดว่าคนเขียนถูกเสมอ

การเลือกภาษาใช้ Python เป็นภาษาสอนตั้งต้นเพื่อลดภาระ syntax แต่ยังต้องอ่าน C/Java และตรวจภาษาหรือ runtime ที่ผู้จัดอนุญาตจริงก่อนรอบเขียนโปรแกรม เอกสารที่อ่านยังไม่ยืนยันว่าทุกโจทย์เลือกใช้ภาษาใดก็ได้

รอบชิงมีระดับ 100/200/300 ตาม PDF ปีนี้ ฝึกเลือกจากความถนัดและความมั่นใจของทีม อย่าวางกลยุทธ์เดาหรือเว้นคำตอบจากสมมติฐานเรื่องคะแนนติดลบ เพราะเอกสารที่อ่านยังไม่ระบุรายละเอียดนี้

## 7. ตัวอย่างงานเขียนโปรแกรมหลังรอบออนไลน์

ทั้งหมดเป็นโจทย์ฝึกที่แต่งใหม่ ไม่ใช่ข้อสอบเก่า

1. รับ `n` และจำนวนเต็ม `n` ตัว แสดงจำนวนเลขคู่และผลรวมเลขคี่; `1 ≤ n ≤ 100000`, ค่าจำนวนเต็มตั้งแต่ `-10^6` ถึง `10^6` ฝึก counter/accumulator และขนาดตัวแปร
2. รับข้อความตัวพิมพ์เล็ก `a–z` ยาว 1–100000 ตัว แสดงอักษรที่พบบ่อยที่สุดและจำนวน; ถ้าเสมอเลือกอักษรก่อนตามตัวอักษร ฝึก frequency และ tie-break
3. รับจำนวนเต็มเรียงจากน้อยไปมากและ `q` ค่าค้นหา แสดงว่าพบแต่ละค่าหรือไม่; `n,q ≤ 100000` ฝึกประเมิน linear search เทียบ binary search
4. หาผลรวมช่วงดัชนีหลายคำถามด้วย prefix sum เมื่อทำพื้นฐานผ่านแล้ว ฝึกนิยาม inclusive/exclusive และทดสอบขอบช่วง

แต่ละงานต้องมี test ขนาดเล็กสุด ค่าเท่ากันทุกตัว ค่าลบ/ศูนย์เมื่อโจทย์อนุญาต และกรณีเสมอ ตรวจผลด้วยวิธีตรงไปตรงมาในข้อมูลเล็กก่อนใช้วิธีเร็ว

### แหล่งเรียนเสริมจากผู้จัดทำเนื้อหาโดยตรง

ไม่จำเป็นต้องอ่านทุกแหล่งก่อนสอบพรุ่งนี้ เลือกอ่านเฉพาะเรื่องที่ผิดจากแบบฝึก

- [Python Tutorial: Control Flow](https://docs.python.org/3/tutorial/controlflow.html): `if`, `for`, `range`, functions; ใช้ตรวจขอบเขตลูปและลองตัวอย่างทีละขั้น

- [NIST SP 800-145](https://csrc.nist.gov/pubs/sp/800/145/final): นิยาม Cloud และรูปแบบบริการ; อ่านส่วน service models หลังเรียน N3 ไม่ต้องท่องทั้งเอกสาร

- [Microsoft: Relative, absolute and mixed references](https://support.microsoft.com/en-us/excel/switch-between-relative-absolute-and-mixed-references): ลองคัดลอกสูตรจริงแล้วทำนายว่าตำแหน่งใดเปลี่ยน

รายการอ่านเพิ่มเติมเป็นแหล่งเรียนสำหรับหลักสูตร ไม่ใช่บรรณานุกรมที่ผู้จัดประกาศใช้ในการออกข้อสอบ

## 9. ข้อมูลที่ยังไม่ยืนยัน

- จำนวนข้อและน้ำหนักรายหมวดของรอบ onsite และสัดส่วนปรนัย/เขียนโปรแกรม
- วิธีคิด partial credit หรือโทษของการเลือกเกินในข้อหลายคำตอบ
- เวลาแต่ละคำถามและรายละเอียดการหักคะแนนรอบชิง
- IDE, compiler/runtime, library และข้อกำหนดการเลือกภาษา
- การย้อนคำถามและเครื่องมืออ้างอิงที่อนุญาตในรอบออนไลน์

ตรวจคำชี้แจงของผู้จัดก่อนสอบจริง หากภายหลังพบประกาศใหม่ให้ปรับเฉพาะส่วนที่เกี่ยวข้อง โดยไม่ถือว่าชุดฝึกนี้มีอำนาจเหนือกติกาจริง
