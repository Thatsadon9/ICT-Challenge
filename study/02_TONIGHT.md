# บทติวคืนนี้: เข้าใจหลักก่อนจำศัพท์

สำหรับคืนวันที่ 25 ตุลาคม 2569 ใช้ร่วมกับแบบฝึก D และ M เนื้อหาและตัวอย่างเรียบเรียงใหม่เพื่อสอน ไม่ใช่ข้อสอบเก่า

เป้าหมายคืนนี้คืออธิบายเหตุผลและอ่านตัวลวงได้ ไม่ใช่เรียนทุกหัวข้อในหลักสูตรจบภายในวันเดียว

## 1. คอมพิวเตอร์และเครือข่าย: ข้อมูลเดินทางอย่างไร

ลองนึกถึงการเปิดเว็บโรงเรียน: เครื่องเราเป็น **client** ส่งคำขอไปยัง **server** โดยมีบริการหลายอย่างทำหน้าที่ต่างกัน

| สิ่งที่พบ | หน้าที่ | ตัวลวงที่ต้องแยก |
|---|---|---|
| CPU | ประมวลผลคำสั่ง | ไม่ใช่ที่เก็บไฟล์ถาวร |
| RAM | พื้นที่ทำงานชั่วคราวของโปรแกรม | RAM ทั่วไปสูญข้อมูลเมื่อปิดไฟ |
| SSD/HDD | เก็บข้อมูลระยะยาว | เพิ่มพื้นที่เก็บไฟล์ไม่ได้แปลว่าคำนวณเร็วขึ้นทุกงาน |
| OS | จัดการทรัพยากรและให้บริการโปรแกรม | ต่างจากแอปที่ทำงานบน OS |
| Switch | ส่ง Ethernet frame ใน LAN โดยอาศัย MAC address | ไม่ใช่บริการแปลชื่อโดเมน |
| Router | ส่ง packet ข้ามเครือข่ายตาม IP/routing | ไม่ใช่ตัวแปลงชื่อเว็บไซต์เป็น IP |
| Access point | เชื่อมอุปกรณ์ไร้สายเข้ากับเครือข่าย | อุปกรณ์ในบ้านอาจรวม AP/router/switch ไว้ในกล่องเดียว |
| DHCP | แจกค่าตั้งเครือข่าย เช่น IP/gateway/DNS ให้ client | ไม่ได้ทำหน้าที่แปลชื่อโดเมน |
| DNS | ค้นระเบียนชื่อ เช่น ชื่อโดเมนไปยัง IP | ไม่ได้ทำหน้าที่แจก IP ให้เครื่อง |

เส้นทางเว็บแบบย่อ เมื่อยังไม่มีข้อมูล cache: เครื่องมีค่าตั้งเครือข่าย → DNS ช่วยหาปลายทาง → เชื่อมต่ออย่างเหมาะสม → ส่ง HTTP request → รับ response → browser แสดงผล เส้นทางจริงอาจมี cache, proxy หรือ CDN เพิ่มได้

**TCP** ให้บริการ byte stream ที่เรียงลำดับและมีการส่งซ้ำเพื่อความน่าเชื่อถือ ส่วน **UDP** ส่ง datagram โดยตัวโปรโตคอลเองไม่รับประกันการส่งถึงหรือเรียงลำดับ แอปบน UDP อาจเพิ่มกลไกเหล่านี้เอง จึงอย่าจำว่า “UDP ใช้กับงานที่ห้ามเชื่อถือไม่ได้ทุกชนิด”

**HTTPS** ใช้ HTTP บนการเชื่อมต่อที่ป้องกันด้วย TLS ช่วยคุ้มครองข้อมูลระหว่างทางและตรวจตัวตนปลายทางตามระบบ certificate แต่ไม่ได้รับประกันว่าเนื้อหาบนเว็บเป็นความจริงหรือผู้ขายสุจริต ไม่จำว่า HTTPS ต้องใช้ TCP เสมอ เพราะ HTTP/3 ใช้ QUIC บน UDP

### คำนวณหน่วยให้ถูกก่อน

- 1 byte = 8 bits; สัญลักษณ์ `b` มักหมายถึง bit และ `B` หมายถึง byte
- `MB` แบบฐานสิบ = 1,000,000 bytes; `MiB` = 1,048,576 bytes ข้อสอบที่ใช้คำว่า KB/MB โดยไม่ชัดต้องอ่านสมมติฐานประกอบ
- ไฟล์ 30 MB ผ่านช่องสัญญาณ 24 Mb/s: ข้อมูล = 30 × 8 = 240 Mb เวลาต่ำสุดเชิงอุดมคติ = 240 ÷ 24 = **10 วินาที** เมื่อไม่คิด overhead และคอขวดอื่น
- binary `1010₂` = 1×8 + 0×4 + 1×2 + 0×1 = **10₁₀**

### IP และ subnet ที่ควรรู้ไว้

IPv4 มี 32 bits; `/24` หมายถึง network prefix 24 bits เหลือ host bits 8 bits จึงมี 2^8 = 256 addresses ใน subnet

สำหรับ IPv4 subnet ปกติแบบนี้ network และ broadcast ใช้เป็น host ไม่ได้ จึงเหลือ 254 hosts เช่น `192.168.1.0/24`: network `.0`, broadcast `.255`, ช่วง host `.1–.254` กฎลบสองนี้ไม่ใช้เหมารวมกับ `/31` หรือ `/32`

คืนนี้ให้เข้าใจเหตุผล ส่วนการแบ่ง `/26` และหลาย subnet ค่อยฝึกหลังสอบออนไลน์

**เช็กความเข้าใจ:** ได้ IP แล้วแต่เปิดชื่อโดเมนไม่ได้ เป็นเหตุให้สงสัย DNS ได้หรือไม่? ได้ แต่ยังไม่ใช่ข้อพิสูจน์ว่าต้องเสียที่ DNS เพียงอย่างเดียว ต้องพิจารณาหลักฐานอื่นด้วย

อ่านเพิ่มเฉพาะถ้ายังสับสน: [MDN: How the web works](https://developer.mozilla.org/en-US/docs/Learn_web_development/Getting_started/Web_standards/How_the_web_works)

## 2. Cloud และ Security: ใครจัดการอะไร ใครทำอะไรได้

### แยก Cloud จากสิ่งที่ผู้ใช้ต้องดูแล

| บริการ | ผู้ใช้จัดการเด่น ๆ | ภาพจำ |
|---|---|---|
| IaaS | OS, application และข้อมูลบน compute ที่เช่า | เช่า VM แล้วติดตั้ง OS/โปรแกรมเอง |
| PaaS | application และข้อมูล; ผู้ให้บริการดูแล platform/runtime ตามบริการ | ส่งโค้ดขึ้น managed app platform |
| SaaS | ตั้งค่าการใช้งาน บัญชี สิทธิ์ และข้อมูลของตน | ใช้เว็บอีเมลหรือเอกสารออนไลน์สำเร็จรูป |

ความรับผิดชอบจริงขึ้นกับบริการและข้อตกลง อย่าใช้ตารางนี้สรุปว่าผู้ใช้ SaaS ไม่ต้องดูแล security เลย ผู้ใช้ยังต้องจัดการสิทธิ์และข้อมูลอย่างเหมาะสม

Public cloud ไม่ได้แปลว่าข้อมูลทุกคนเปิดสาธารณะ ส่วน serverless ไม่ได้แปลว่าไม่มี server แต่ผู้ใช้ไม่ต้องบริหาร server แต่ละเครื่องโดยตรง

### Security แยกให้ได้ 5 คู่

1. **Authentication / Authorization:** “คุณเป็นใคร” กับ “คุณมีสิทธิ์ทำอะไร” ล็อกอินได้แต่เปิดไฟล์เงินเดือนไม่ได้เป็นเรื่องสิทธิ์ ไม่จำเป็นว่าระบบล็อกอินเสีย
2. **Confidentiality / Integrity / Availability:** ไม่ให้คนไม่มีสิทธิ์เห็น / ไม่ให้แก้ข้อมูลโดยมิชอบ / ใช้ระบบได้เมื่อจำเป็น; การมี backup ช่วยกู้คืน แต่ไม่ทำให้ระบบพร้อมใช้ตลอดเวลาโดยอัตโนมัติ
3. **Encryption / Hashing:** encryption ใช้กุญแจเพื่อถอดกลับตามระบบ ส่วน hash สร้าง digest และออกแบบให้ย้อนหาข้อมูลต้นฉบับยาก; hash ไม่ใช่การเข้ารหัสที่ถอดได้ด้วยกุญแจ และไม่ได้ทำให้เดารหัสผ่านสั้น ๆ ไม่ได้
4. **MFA / รหัสสองชุด:** หลายปัจจัยต้องเป็นคนละประเภท เช่น password (สิ่งที่รู้) + security key (สิ่งที่มี); password + PIN ยังเป็นปัจจัยประเภทเดียวกัน
5. **Phishing / Malware:** phishing หลอกให้ทำบางอย่าง เช่น กรอกรหัสหรือเปิดไฟล์ ส่วน malware คือซอฟต์แวร์อันตราย ทั้งสองอาจเกิดร่วมกัน

ตัวอย่าง: อีเมลบอกให้รีบล็อกอินผ่านลิงก์เพื่อไม่ให้บัญชีถูกปิด วิธีคิดคือแยกความเร่งด่วนออกจากหลักฐาน ตรวจผ่านช่องทางที่รู้จัก เปิดเว็บทางการเอง และไม่ส่งรหัสหรือ OTP ไปให้คนอื่น การเปิดใช้ MFA ช่วยลดความเสี่ยงแต่ไม่ได้ทำให้การหลอกทุกแบบล้มเหลว

**Least privilege:** ให้สิทธิ์เท่าที่จำเป็น เช่น คนรับข้อมูลแบบฟอร์มไม่ต้องมีสิทธิ์ลบฐานข้อมูลทั้งระบบ

**เช็กความเข้าใจ:** คนหนึ่งเปลี่ยนราคาสินค้าในฐานข้อมูลโดยไม่ได้รับสิทธิ์ กระทบ CIA ด้านใดตรงที่สุด? **Integrity** แม้เหตุการณ์จริงอาจมีผลต่อด้านอื่นร่วมด้วย

อ่านเพิ่มภายหลัง: [NIST: Cloud Computing](https://csrc.nist.gov/pubs/sp/800/145/final)

## 3. Programming: อ่านทีละคำสั่งและระบุขอบเขต

อย่าพยายามเดาผลลัพธ์จากหน้าตาโค้ด ให้ทำ **trace table**: ก่อนเข้าลูปมีค่าเท่าใด แต่ละรอบตรวจอะไร แล้วเปลี่ยนค่าอะไร

```python
s = 0
for i in range(1, 6):
    if i % 2 == 0:
        s += i
print(s)
```

| i | เป็นเลขคู่หรือไม่ | s หลังรอบ |
|---|---|---|
| 1 | ไม่ | 0 |
| 2 | ใช่ | 2 |
| 3 | ไม่ | 2 |
| 4 | ใช่ | 6 |
| 5 | ไม่ | 6 |

คำตอบคือ **6** เพราะ `range(1, 6)` ไม่รวม 6 ไม่ใช่การรวม 2+4+6

### ความต่างภาษาเบื้องต้น

| งาน | Python 3 | C / Java ในกรณีที่ระบุ |
|---|---|---|
| หาร `5 / 2` | `2.5` | เมื่อ operands เป็น integer ทั้งคู่ ได้ `2` |
| หารปัดลง | `5 // 2` ได้ `2` | integer division เป็นการตัดเข้าหาศูนย์; ตรงกับ floor เฉพาะบางกรณี เช่นจำนวนบวก |
| เปรียบเทียบเท่ากัน | `==` | `==` เช่นกันสำหรับค่าพื้นฐาน; การเทียบ string/object ต้องเรียนกฎของภาษานั้นเพิ่ม |
| กำหนดค่า | `=` | `=` |
| สมาชิก array/list ตัวแรก | index 0 | index 0 |
| ขอบเขตลูป | `range(n)` คือ 0 ถึง n−1 | `for (int i=0; i<n; i++)` เช่นกัน |

ตัวอย่างจำนวนลบที่ไม่ควรจำข้ามภาษา: Python `-7 // 2` ได้ `-4` แต่ C รุ่นมาตรฐานใหม่และ Java เมื่อหาร integer `-7 / 2` ได้ `-3`

### ฟังก์ชันและบั๊กที่พบบ่อย

```python
def count_even(values):
    count = 0
    for value in values:
        if value % 2 == 0:
            count += 1
    return count
```

`return` อยู่หลังลูปจึงนับทุกตัว ถ้าเยื้องให้ return อยู่ในลูปจะจบหลังตรวจตัวแรก ให้ลอง `[1, 2, 4]`: ค่าที่ถูกต้องคือ 2

จุดตรวจเมื่ออ่านโค้ด: ค่าเริ่มต้น → เงื่อนไข → จำนวนรอบ → การอัปเดต → จุด return และต้องแยกว่าเกิด syntax error, runtime error หรือ logic error

### Algorithms ที่คุ้มก่อน

- Linear search ตรวจทีละตัว ใช้กับข้อมูลไม่เรียงได้ กรณีแย่สุดตรวจ `n` ตัว
- Binary search ตัดช่วงค้นหาครึ่งหนึ่งซ้ำ ๆ แต่ต้องมีเงื่อนไขที่ทำให้เลือกครึ่งได้ถูก เช่น array ที่เรียงแล้ว; เวลา O(log n) สำหรับการเข้าถึงแบบ array
- ลูปหนึ่งรอบผ่าน n ตัวมักเป็น O(n) หากงานต่อรอบคงที่; ลูปสองชั้นที่แต่ละชั้นวิ่ง n รอบมักเป็น O(n²) แต่ไม่ใช่ทุก nested loop จะเป็น O(n²)
- อย่าสับสนว่าโค้ดบรรทัดสั้นแปลว่าทำงานเร็ว ต้องดูจำนวนงานเมื่อ input โต

**เช็กความเข้าใจ:** เปลี่ยน `i < n` เป็น `i <= n` แล้วอ่าน `a[i]` ใน array ขนาด n อาจเกิดอะไร? เข้าถึง index n ซึ่งเกินขอบเขต; พฤติกรรมรายละเอียดขึ้นกับภาษา

อ่านเพิ่ม: [Python Control Flow](https://docs.python.org/3/tutorial/controlflow.html)

## 4. Data และ AI: ข้อมูลถูกหรือไม่ วัดอะไร และตอบได้แค่ไหน

### เริ่มจากข้อมูลก่อนโมเดล

Numeric คือค่าปริมาณที่การคำนวณมีความหมาย เช่น น้ำหนัก ส่วน categorical เป็นกลุ่ม เช่น ชนิดสินค้า หมายเลขห้องอาจเขียนเป็นตัวเลขแต่เป็นรหัสกลุ่ม ไม่ควรคำนวณค่าเฉลี่ยโดยอัตโนมัติ

ข้อมูล `10, 10, 10, 10, 100` มี mean = 28 และ median = 10 ค่าปลายสุดดึง mean ได้มากกว่า จึงต้องเลือกสถิติให้ตรงคำถาม ไม่ใช่ตัด outlier ทิ้งทุกครั้ง

ข้อมูลหายไม่ได้แปลว่าเป็นศูนย์ ถ้ารายได้ยังไม่บันทึก การแทนด้วย 0 อาจทำให้สรุปผิด ต้องเข้าใจเหตุที่หายและวิธีจัดการก่อน

เลือกกราฟให้เป้าหมาย: เปรียบเทียบหมวดใช้ bar chart, ดูแนวโน้มเวลามักใช้ line chart, ดูการกระจายตัวแปรเดียวใช้ histogram, ดูความสัมพันธ์สองตัวแปรเชิงปริมาณใช้ scatter plot ความสัมพันธ์ที่เห็นไม่ยืนยันเหตุและผล

### แยกงาน Machine Learning

| คำถาม | งาน |
|---|---|
| อีเมลเป็น spam หรือไม่ | Supervised classification |
| บ้านหลังนี้น่าจะมีราคาเท่าไร | Supervised regression |
| จัดกลุ่มลูกค้าจากพฤติกรรมโดยไม่มีป้ายกลุ่ม | Unsupervised clustering |
| Agent เลือกการกระทำและเรียนจาก reward | Reinforcement learning |

Classification ทำนายกลุ่ม; regression ทำนายค่าปริมาณ ไม่ใช่ตัดสินจาก input เป็นข้อความหรือตัวเลข

### โมเดลเก่งจริงหรือจำคำตอบ

- Training set ใช้เรียนพารามิเตอร์
- Validation set ใช้เลือกแบบจำลองหรือ hyperparameters
- Test set ใช้ประเมินครั้งสุดท้าย โดยไม่คอยปรับตามผล test ซ้ำ ๆ
- **Overfitting:** ทำได้ดีบน train แต่ generalize ไม่ดีบนข้อมูลใหม่
- **Data leakage:** ข้อมูลที่ไม่ควรรู้ขณะทำนายรั่วเข้าไปในการฝึกหรือประเมิน เช่น ทำนายว่าจะสอบผ่านโดยใช้คะแนนสอบครั้งนั้นเป็น feature

ตัวอย่าง accuracy หลอกตา: มีอีเมลปกติ 990 ฉบับและ spam 10 ฉบับ โมเดลทาย “ปกติ” ทุกฉบับได้ accuracy 99% แต่จับ spam ไม่ได้เลย

ให้ “spam” เป็น positive:

- Precision = TP / (TP + FP): ในสิ่งที่เราบอกว่าเป็น spam มี spam จริงกี่ส่วน
- Recall = TP / (TP + FN): ใน spam จริงทั้งหมด เราจับได้กี่ส่วน
- TP = บอก positive แล้วถูก, FP = บอก positive แต่ผิด, FN = พลาด positive จริง, TN = บอก negative แล้วถูก

ถ้า TP=18, FP=6, FN=2: precision = 18/24 = 75%, recall = 18/20 = 90% สองค่านี้ตอบคนละคำถาม

### Generative AI และ Prompt

GenAI สร้างเนื้อหาใหม่ เช่น ข้อความ/ภาพ การตอบลื่นไหลหรือมีบรรณานุกรมไม่ได้รับประกันความจริง ต้องตรวจแหล่งอ้างอิงและไม่ใส่ข้อมูลอ่อนไหวโดยไม่จำเป็น

Prompt ที่ตรวจผลได้ควรมี **เป้าหมาย + บริบท/ข้อมูล + เงื่อนไข + รูปแบบผลลัพธ์** เช่น “จากตารางที่ให้ จัดรายการข้อมูลที่ขาดหาย ห้ามสมมติค่าที่ไม่มี และตอบเป็นตารางคอลัมน์แถว/ปัญหา/วิธีตรวจ” การระบุบทบาทเพียงอย่างเดียวไม่ทดแทนข้อมูลและเกณฑ์ตรวจ

Hallucination คือการสร้างข้อความที่อาจไม่ตรงข้อเท็จจริงหรือหลักฐานที่กำหนด การให้เอกสารอ้างอิงช่วยได้ แต่ไม่รับประกันว่าจะไม่เกิดข้อผิดพลาด

อ่านเพิ่มหลังคืนนี้: [Google ML Crash Course](https://developers.google.com/machine-learning/crash-course) เฉพาะโมดูลที่เกี่ยวข้อง

### สูตรและ reference

| Reference | ล็อกอะไร |
|---|---|
| `A1` | ไม่ล็อกแถวหรือคอลัมน์ |
| `$A$1` | ล็อกทั้งคอลัมน์ A และแถว 1 |
| `$A1` | ล็อกคอลัมน์ A แต่แถวเลื่อนได้ |
| `A$1` | ล็อกแถว 1 แต่คอลัมน์เลื่อนได้ |

ที่ C2 มี `=B2*$F$1` เมื่อคัดลอกลง C3 จะเป็น `=B3*$F$1` เพราะราคาหรือจำนวนใน B เปลี่ยนตามแถว แต่อัตราใน F1 ต้องคงเดิม

- `SUM` รวมค่า, `AVERAGE` ค่าเฉลี่ย, `COUNTIF` นับตามเงื่อนไข, `IF` เลือกผลตามเงื่อนไข
- Sorting จัดลำดับข้อมูล; filtering แสดงเฉพาะข้อมูลที่เข้าเงื่อนไข ต้องระวัง sort เพียงคอลัมน์เดียวจนข้อมูลแต่ละคนไม่ตรงแถว
- การแชร์ link ต้องดูสิทธิ์ viewer/commenter/editor และขอบเขตคนที่เข้าถึงได้ด้วย
- Version history ช่วยติดตาม/คืนงานเก่า แต่ไม่ใช่เหตุให้ให้ทุกคนแก้ไขได้โดยไม่มีขอบเขต
- CSV เก็บข้อมูลตารางแบบข้อความ ไม่เก็บหลาย worksheet และรูปแบบการจัดหน้าครบเหมือน workbook
- Automation ขั้นต้นมักคิดเป็น trigger → ตรวจเงื่อนไข → action เช่น เมื่อรับแบบฟอร์ม → ตรวจช่องจำเป็น → เพิ่มแถวและแจ้งสถานะ ต้องมีวิธีรับมือข้อมูลผิดหรือซ้ำ

## 6. วิธีทำข้อเลือกหลายคำตอบ

อ่านคำถามก่อนว่าต้องการ “ถูก”, “ผิด”, “เหมาะที่สุด” หรือ “เลือกทุกข้อที่ถูก” จากนั้นตัดสิน **แต่ละตัวเลือกอย่างอิสระ** ไม่เลือกเพิ่มเพราะคิดว่าต้องมีคำตอบสองข้อเสมอ

คำว่า “เสมอ”, “ทุกกรณี”, “รับประกัน” เป็นเหตุให้ตรวจเงื่อนไขเพิ่ม ไม่ใช่เหตุให้ตัดทิ้งอัตโนมัติ ตัวอย่าง “1 byte มี 8 bits” เป็นข้อความเด็ดขาดที่ถูกได้

ในชุดฝึกให้เขียนเหตุผลของตัวเลือกที่ไม่เลือกด้วย การคิดคะแนนข้อหลายคำตอบจริงต้องอ่านจากคำชี้แจงผู้จัด ไม่สมมติว่ามี partial credit
